# Design: набор частот блока в портрете эфира

**Date:** 2026-09-14  
**Status:** approved for planning  
**Approach:** 1 — `integer[]` на портрете + константа каталога в коде

## Problem

`BroadcastPortrait` хранит одно `block_frequency_per_hour` (integer 1..60). Генератор режет час шагом `3600 / N`, а форма заказа даёт свободный ввод `shows_per_hour`. Нужен фиксированный каталог частот и набор допустимых значений **на портрете**; конкретную частоту выбирает заказ после выбора экранов, из пересечения наборов.

## Goals

- Портрет хранит **набор** допустимых частот из каталога `1, 2, 3, 4, 5, 6, 10, 12, 20`.
- Оператор отмечает подмножество чекбоксами. Одно «текущее N» на портрете не хранится.
- Заказ: сначала экраны, затем одно `shows_per_hour` из пересечения наборов выбранных экранов.
- Генератор режет каждый локальный час по НОК частот occupying commercial-заказов этого часа (без таких заказов — `max` набора портрета).
- Живые заказы при сужении набора портрета не откатываем.

## Non-goals

- Справочник частот в БД и расширение каталога без деплоя.
- Ограничение ручного `MediaPlan` (`media_plans` number_field) каталогом портрета.
- Отдельная таблица `broadcast_portrait_frequencies`.
- Тип портрета `timed`.
- Пересчёт или отмена уже активных заказов, чья частота выпала из набора портрета.

## Why This Approach

| Option | Verdict |
|--------|---------|
| 1 — `integer[]` + константа каталога | Выбрано: значения не сущности, один столбец, пересечение в SQL (`&&`), копия шаблона копирует массив |
| 2 — таблица `(portrait_id, frequency)` | Отклонено: девять чисел каталога не требуют FK и JOIN |
| 3 — `jsonb` массив | Отклонено: слабее тип и check, нет выигрыша |

Разветвления продукта, зафиксированные до хранения:

- Набор на портрете, без скаляра N; выбор частоты — на заказе (`shows_per_hour`).
- Структура часа — от заказов (НОК), не от скаляра портрета.
- Каталог только в коде; в портрете — подмножество, чекбоксы.
- Несколько экранов в заказе: допустима только частота из **пересечения**; пустое пересечение — такой набор экранов недопустим.

## Data model

Каталог (не таблица):

```ruby
BroadcastPortrait::BLOCK_FREQUENCIES_PER_HOUR = [1, 2, 3, 4, 5, 6, 10, 12, 20].freeze
```

Колонка `broadcast_portraits.block_frequencies_per_hour integer[] NOT NULL`. Скаляр `block_frequency_per_hour` удаляется в той же миграции.

Перед записью модель нормализует массив: уникальные целые, сортировка по возрастанию. Check-constraints:

- `cardinality(block_frequencies_per_hour) >= 1`
- `block_frequencies_per_hour <@ ARRAY[1,2,3,4,5,6,10,12,20]::integer[]`

Пустой набор запрещён: без заказов нечем резать час, пересечение с любым заказом пустое.

**Backfill:** если старое значение ∈ каталога → `ARRAY[n]`. Иначе — наибольшее значение каталога, которое ≤ n; если таких нет — минимум каталога. Следствие: `8` → `6`. Дефолт новой формы портрета — `[4]` (как нынешний скаляр по умолчанию).

`Portraits::CopyTemplate` копирует массив целиком. Fingerprint портрета хеширует отсортированный массив, не скаляр. Ransack: скаляр убрать из `ransackable_attributes`; поиск по массиву не добавляем.

Админка портрета: чекбоксы каталога вместо `number_field`; show — список значений. i18n: ключ атрибута во множественном числе (`block_frequencies_per_hour`).

## Order form

Кабинет и админка — общая `_form`.

1. Выбор экранов (пикер как сейчас).
2. Пересечение `block_frequencies_per_hour` портретов отмеченных экранов (на строке пикера — `data` с набором).
3. `shows_per_hour` — `select` только из пересечения, по возрастанию. Нет экранов или пустое пересечение — селект disabled, сетка не считает выходы.
4. Смена экранов пересобирает options. Если прежняя частота выпала — сброс, невалидное значение не оставляем.

Сервер — источник правды:

- Экраны есть, пересечение пустое → ошибка на наборе экранов, частоту не сохраняем.
- Экраны есть, `shows_per_hour` не из пересечения → ошибка на `shows_per_hour`.
- Черновик без экранов: `shows_per_hour` может остаться `nil` (как сейчас до заполнения формы).

Одно значение на весь заказ, как сегодня. Ячейки сетки по-прежнему `shows_per_hour ×` часы пересечения окон. Активация по-прежнему пишет `order.shows_per_hour` в медиаплан заявки.

## Playlist generation

Для каждого **календарного часа локали экрана**, пересечённого рабочими окнами:

1. Частоты occupying **commercial**-планов с `shows_per_hour` **из каталога**, которые покрывают этот час.
2. `N = НОК(этих частот)`. Нет таких планов → `N = max(portrait.block_frequencies_per_hour)`.
3. Час 00…60 мин этого clock-hour = N равных слотов длительностью `3600 / N` секунд. Индекс удара `i` — от начала этого clock-hour. Слоты вне рабочего окна отбрасываются. Все значения каталога делят 60, НОК тоже делит 60; шаг — целые минуты (худший случай — 60 слотов по 1 минуте).

Commercial с `shows_per_hour` вне каталога (ручной медиаплан, вне скоупа ограничения) в НОК не входит: клип в слотах, которые уже возникли из каталожных частот или из `max` портрета, по правилам mixed/max_in_row. Если в часе только такие планы — как «нет каталожных», N = max набора портрета.

План с частотой `f` имеет удар в слоте `i` (0…N−1), если `i % (N / f) == 0`. Пример: 4 и 6 → N=12; 4 играет в `0,3,6,9`; 6 — в `0,2,4,6,8,10`; слоты `0` и `6` — mixed.

- В слоте-ударе план даёт **один** клип (один выход). Иначе `shows_per_hour` перестаёт означать число выходов.
- Несколько планов в одном слоте — нынешний mixed: round-robin, суммарно не больше `max_commercial_in_row`.
- Слот без ударов — filler из портрета.
- Шапки оборачивают commercial-слот; welcome/close и insertion без изменений.

Цикл портрета больше не задаёт, сколько раз в час будет рекламный блок. Портрет задаёт, что вокруг блока (шапки, нейтралка, вставки) и какие частоты допустимы.

`own_atmosphere` без `shows_per_hour` в НОК не входит. Формула `ceil(shows_per_hour / old_N)` удаляется.

Правка набора на портрете экрана — `Playlists::EnqueueRegen`, как сейчас правка скаляра.

## Error handling

| Ситуация | Поведение |
|----------|-----------|
| Портрет без чекбоксов / пустой массив | Ошибка на `block_frequencies_per_hour` |
| Значение вне каталога | Нормализация + check; запись не проходит |
| Сузили набор, живой заказ со старой частотой | Не откатываем occupy; форма заказа больше не предложит выбывшее значение |
| Пустое пересечение экранов заказа | Ошибка на экранах |
| Частота вне пересечения (в т.ч. после смены экранов на edit) | Ошибка на `shows_per_hour` до выбора нового значения |
| Нет клипов в ротации | Нынешние warning; generate не падает |
| Ручной медиаплан с произвольным `shows_per_hour` | Вне скоупа, каталогом портрета не режем |

## Testing

- Модель: нормализация; отказ пустого набора и внекаталожного числа; валидный поднабор.
- Backfill-правило `8 → 6` в spec миграции или эквивалентном примере.
- `CopyTemplate` копирует массив. Fingerprint меняется при смене набора.
- Генератор: без заказов шаг = `max` набора; 4 и 6 → 12 слотов и удары как выше; слот без удара — filler.
- Хелпер портрета в spec: вместо скаляра `frequency:` — массив.
- Заказ (request + system, кабинет и админка через общую форму): экраны раньше частоты; `select` из пересечения; пустое пересечение и частота вне пересечения не сохраняются.
- Админка портрета: чекбоксы каталога вместо `number_field`.
