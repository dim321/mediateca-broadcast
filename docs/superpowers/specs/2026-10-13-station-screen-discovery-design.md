# Обнаружение экранов станции — дизайн

## Цель

Оператор со страницы станции в админке запускает обнаружение телевизоров в
локальной сети. Hub ставит станционную команду `fetch_screens` в существующую
очередь. Агент станции читает активные DHCP-аренды dnsmasq и возвращает пары
MAC/IP. Hub синхронизирует их с экранами только этой станции.

Существующие экранные команды продолжают работать без изменения их
семантики. `GET /api/agent/v1/commands` и
`POST /api/agent/v1/command_results` остаются общими точками обмена.

## Принятые решения

- Идентификатор найденного телевизора — MAC в пределах станции.
- Изменение IP обновляет существующий экран, а не создаёт новый.
- Экран, отсутствующий в очередном успешном результате, получает
  `network_registered = false`; он не удаляется.
- Имена назначаются по возрастанию IP только новым экранам. Существующие
  имена не меняются.
- Повторное нажатие кнопки не создаёт вторую pending-команду `fetch_screens`.
- `fetch_screens` — команда станции, поэтому её `screen_id` равен `null`.

## Схема данных

В `screens` добавляются:

```ruby
t.inet :ip_address
t.macaddr :mac_address
t.boolean :network_registered, null: false, default: false
```

`inet` и `macaddr` — встроенные типы PostgreSQL 18, расширения не нужны.
Rails отображает `inet` в `IPAddr`, а `macaddr` — в каноническую строку.

Частичный уникальный индекс на `(station_id, mac_address)` для непустых MAC
защищает идентичность экрана внутри станции. Один MAC допустим у экранов
разных станций. На IP уникального индекса нет: адрес может быть повторно
выдан другому телевизору, пока старый экран сохраняет последний известный IP.

В `agent_commands` внешний ключ `screen_id` становится nullable.
Модель требует:

- отсутствующий `screen` для `fetch_screens`;
- присутствующий экран той же станции для всех остальных типов команд.

Частичный уникальный индекс по `station_id` с условием
`status = 'pending' AND command_type = 'fetch_screens'` исключает две
одновременные команды обновления на станцию.

## Постановка команды из админки

У станции появляется вложенный singular endpoint создания обновления экранов,
например `POST /admin/stations/:station_id/screen_refresh`.

Тонкий admin-контроллер вызывает доменный сервис постановки команды. Сервис:

1. находит существующую pending-команду `fetch_screens`;
2. возвращает её либо создаёт команду с новым `cmd_<uuid>`, пустыми `params`
   и текущим `issued_at`;
3. обрабатывает конкурентный `RecordNotUnique` повторным чтением команды.

Ответ — `303 See Other` обратно на страницу станции. Flash различает
«обновление запрошено» и «обновление уже ожидает выполнения».

## Контракт команды

`GET /api/agent/v1/commands` возвращает:

```json
{
  "commands": [
    {
      "id": "cmd_7b03539f-6ea8-4cf0-a719-1831b833f639",
      "screen_id": null,
      "type": "fetch_screens",
      "params": {},
      "issued_at": "2026-10-13T14:00:00Z"
    }
  ]
}
```

Наличие ключа `screen_id` сохраняет стабильную форму элементов очереди.
Значение `null` явно обозначает станционную команду.

## Контракт результата

Успешный результат:

```json
{
  "results": [
    {
      "command_id": "cmd_7b03539f-6ea8-4cf0-a719-1831b833f639",
      "ok": true,
      "error": null,
      "finished_at": "2026-10-13T14:00:03Z",
      "result": {
        "screens": [
          {
            "mac_address": "aa:bb:cc:dd:ee:ff",
            "ip_address": "192.168.1.10"
          }
        ]
      }
    }
  ]
}
```

Неуспешный результат сохраняет существующую форму и не содержит обязательного
`result`:

```json
{
  "results": [
    {
      "command_id": "cmd_7b03539f-6ea8-4cf0-a719-1831b833f639",
      "ok": false,
      "error": "lease_file_unreadable",
      "finished_at": "2026-10-13T14:00:03Z"
    }
  ]
}
```

Для остальных типов команд `result` необязателен и не меняет их обработку.

## Валидация результата

Для успешного `fetch_screens` обязательны `result` и массив
`result.screens`. Пустой массив корректен.

Каждая запись должна содержать:

- шестибайтовый MAC, принимаемый PostgreSQL `macaddr`;
- IPv4 host-адрес без CIDR-суффикса.

Hub канонизирует MAC в lowercase-формат с двоеточиями. Полные повторы одной
пары дедуплицируются. Один MAC с разными IP или один IP с разными MAC в одном
payload делает весь результат некорректным.

Некорректный payload возвращает HTTP 422 `{"error":"invalid_result"}`.
Команда остаётся pending, а экраны не меняются.

## Синхронизация

`Agent::Commands::Acknowledge` отвечает за протокол подтверждения, а отдельный
доменный сервис синхронизации — за экраны. Для успешного `fetch_screens`
синхронизация и перевод команды в `acked` выполняются в одной транзакции.

Сервис блокирует строку станции и:

1. загружает экраны станции по MAC;
2. обновляет IP найденных экранов и устанавливает
   `network_registered = true`;
3. устанавливает `network_registered = false` всем экранам, MAC которых нет
   в результате;
4. сортирует неизвестные пары по числовому значению IPv4;
5. создаёт экраны в этом порядке, используя существующий
   `Station#next_screen_name`.

Новые экраны получают стандартные значения модели для ориентации,
операционных часов и владельца. Синхронизация не меняет имена, эфирные
настройки и связи существующих экранов.

Неуспешный результат (`ok: false`) только подтверждает команду с ошибкой.
Состояние экранов не меняется. Неизвестный `command_id`, команда другой
станции и повторный результат уже подтверждённой команды сохраняют текущую
идемпотентную семантику endpoint.

## Админка

На `admin/stations/show` перед телеметрией появляется Flowbite-секция
«Экраны станции». В заголовке расположена кнопка «Обновить экраны».

Таблица содержит:

- имя со ссылкой на admin show экрана;
- MAC-адрес;
- IP-адрес;
- признак регистрации в сети станции.

Пустое состояние явно сообщает, что экраны ещё не добавлены. Используются
Tailwind/Flowbite-классы и существующие admin helpers; daisyUI в админку не
добавляется. Все надписи имеют русские и английские i18n-ключи.

## Ошибки и атомарность

- Ограничение БД защищает от конкурентных pending-команд.
- Блокировка станции и уникальный MAC-индекс защищают от конкурентного
  создания экранов и конфликтов имён.
- Ошибка в любой записи откатывает всю синхронизацию и ack.
- Ошибка чтения leases на агенте не снимает регистрацию с экранов: агент
  отправляет `ok: false`, поэтому синхронизация не запускается.
- Только успешный пустой список снимает регистрацию со всех экранов станции.

## Тестирование Hub

Миграции и модели:

- `inet`, `macaddr`, default `network_registered = false`;
- nullable `agent_commands.screen_id`;
- один MAC уникален внутри станции и допустим между станциями;
- `fetch_screens` без экрана валиден, остальные команды без экрана невалидны;
- БД запрещает две pending-команды обновления одной станции.

Domain specs:

- создание новых экранов в числовом порядке IP;
- обновление IP существующего MAC без переименования;
- снятие регистрации с отсутствующих MAC;
- успешный пустой список;
- дедупликация одинаковых пар;
- отклонение конфликтующих и некорректных пар;
- атомарный rollback;
- межстанционная изоляция и повторная обработка результата.

Request specs:

- секция и поля экранов на странице станции;
- первая и повторная постановка команды;
- `screen_id: null` в очереди;
- успешный и неуспешный результат;
- HTTP 422 при нарушении контракта.

Финальная проверка выполняется командой:

```bash
docker compose exec -e RAILS_ENV=test web bin/ci
```

## Вне scope

- Автоматический периодический запуск обнаружения.
- Удаление экранов, отсутствующих в leases.
- Перенос экрана между станциями по глобальному MAC.
- Переименование уже существующих экранов по IP.
- Поиск телевизоров вне файла dnsmasq leases.
