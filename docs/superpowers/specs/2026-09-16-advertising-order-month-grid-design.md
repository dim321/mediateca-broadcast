# Сетка выходов по месяцам в заказе на размещение

## Цель

На странице создания заказа в админке (`/admin/advertising_orders/new`) разделять
сетку выходов по месяцам, если выбранный период заказа охватывает несколько
месяцев. Каждый месяц должен начинаться отдельным блоком таблицы с повторёнными
строками экранов и собственными датами.

Названия месяцев на русском должны быть в именительном падеже и с заглавной
буквы: `Сентябрь 2026`, а не `сентября 2026`.

## Решение

- Подготовить месячные блоки на стороне Rails helper.
- Рендерить каждый блок отдельным partial таблицы.
- Для каждого блока передавать:
  - месяц;
  - даты только этого месяца;
  - строки заказа, чтобы повторить экраны в каждом месяце;
  - общий контроллер Stimulus для работы с редактированием сетки.
- В ячейках месяца использовать существующую логику определения выходов,
  часов работы и общего количества показов.
- При периоде внутри одного месяца внешний результат должен оставаться одной
  таблицей без изменения поведения.
- Заголовок месяца форматировать через локализованные названия месяцев в
  именительном падеже, без использования `I18n.l(..., format: '%B %Y')`.
- Английская локаль должна продолжить отображать английские названия месяцев.

## Границы изменения

Изменяются только представление сетки нового/редактируемого заказа, связанные
view-helper/partial и тесты. Расчёт заказов, доменные сервисы и API не меняются.

## Тестирование

Добавить проверки, что:

1. период в одном месяце рендерит один блок;
2. период на границе месяцев рендерит два блока;
3. каждый блок содержит только даты своего месяца;
4. русская локаль отображает месяцы в именительном падеже и с заглавной буквы;
5. строки экранов и поля сетки присутствуют в каждом месячном блоке.

Запускать тесты внутри Compose web-контейнера:

```bash
docker compose exec -e RAILS_ENV=test web bundle exec rspec
```
