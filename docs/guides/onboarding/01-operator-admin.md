# Онбординг администратора оператора

Что завести в пустой системе, чтобы клиенты могли работать: флот экранов, организации, пользователи и справочники.

**Кому:** администратор организации-оператора.  
**Где:** админка `/admin` (после входа в приложение).  
**Пример сети:** оператор **Advertising company**, клиенты **Командор** и **Аллея**.

В пустой базе операторская организация и её администратор появляются из сидов (`db/seeds.rb`) или создаются вручную. В системе может быть **только одна** организация с типом `operator`.

---

## 1. Иерархия флота: локация → станция → экран

Флот — общий каталог точек показа. Он не принадлежит клиенту. Клиенты только используют его: ставят свой контент на экраны или вешают свои экраны на уже существующие локации и станции.

```text
Локация          место (магазин, ТЦ, улица)
  └── Станция    устройство / плеер (агент на железе)
        └── Экран  поверхность показа (витрина, монитор у кассы)
```

| Уровень | Что это | Пример |
|---------|---------|--------|
| **Локация** | Физическое место с расписанием работы | Локация 1, Локация 2, Локация 3 |
| **Станция** | Плеер в этой локации. У станции свой токен агента для выдачи эфирного пакета | Станция A, Станция B |
| **Экран** | Конкретный монитор на станции. Имя уникально в пределах станции | Витрина 1 на Станция A |

На одной локации несколько станций. На одной станции несколько экранов (разные ориентации, разные зоны зала).

**Часы работы задаются на локации**, не на экране. Они нужны как знаменатель **коммерческой квоты**: сколько эфирного времени в часе (или в дне) доступно под чужую рекламу. Без часов работы квоту на группу с экранами этой локации сохранить нельзя.

В примере у всех трёх локаций окно **09:00–21:00** каждый день недели.

## 2. Владелец экрана: флот оператора и экраны клиента

У экрана поле владельца необязательное.

| Владелец | Смысл | Кто создаёт |
|----------|--------|-------------|
| **Не задан** | Экран флота оператора. Любой клиент может набрать его в свою «Группу экранов» из каталога сети | Администратор оператора в админке |
| **Клиент** (например Командор) | Собственный экран клиента. Другие клиенты ставят на него коммерцию **только** через именованную группу владельца | Клиент в ЛК («Мои экраны») или оператор в админке с указанием организации-владельца |

Правила, которые нельзя обойти:

- Владельцем может быть только организация-**клиент**, не оператор.
- Коммерческая квота вешается на **группу**, все экраны которой принадлежат одной клиентской организации — той же, что владеет группой.
- Чужой клиент (Аллея) не может поставить на экраны Командора «собственный / атмосфера». Только тип размещения **коммерческий**, и только на группу владельца (**Витрины Командор**).

Практический вывод для пустой сети: оператор поднимает **места и плееры** (локации и станции). Экраны флота — если сеть сдаёт свои мониторы. Экраны «чужого» ритейла (витрины Командора) клиент заводит сам, привязывая их к вашим локациям и станциям.

## 3. Порядок запуска пустой системы

Все пункты — в админке `/admin`. Войдите учётной записью оператора (в примере `admin@advertising.test`), затем откройте админку.

### Шаг 1. Клиентские организации

Создайте организации с типом **client**:

- **Командор**
- **Аллея**

Задайте часовой пояс (в сидах для этой сети — `Krasnoyarsk`). Окна медиапланов клиент вводит в поясе своей организации.

### Шаг 2. Пользователи клиентов

Для каждой клиентской организации — учётная запись с ролью **manager** (контент и размещение) или **administrator** (то же плюс финансы).

Пример:

- Командор → `manager@komandor.test`, роль manager  
- Аллея → `manager@alleya.test`, роль manager  

Роль **accountant** видит только финансы и не ведёт эфир.

### Шаг 3. Локации и часы работы

Создайте локации, например **Локация 1**, **Локация 2**, **Локация 3**.

На форме локации заполните недельное расписание. Пустой день = закрыто. Кнопка «Скопировать пн на все дни» размножает понедельник.

Без расписания клиент не сможет включить коммерческую квоту на группу, в которую войдут экраны этой локации.

### Шаг 4. Станции

На каждой локации создайте станции, например **Станция A** и **Станция B**.

Плееру нужен **токен агента** станции: без него устройство не заберёт эфирный пакет. В текущей версии токен выдаётся методом `Station#assign_agent_token!` (консоль / операция внедрения), в форме админки хранится только хеш `agent_token_digest`.

### Шаг 5. Экраны оператора (флот)

Если сеть показывает рекламу на **своих** мониторах, создайте экраны без владельца: имя, ориентация (альбомная / портретная), станция.

Если на старте все витрины — собственность ритейла, флот-экраны можно не создавать: клиент заведёт **Витрина 1…3** сам в «Мои экраны», выбрав Локация 1 / Станция A.

Оператор может создать экран клиента и в админке, указав `owner_organization` = Командор. Обычно это делают, когда экран уже стоит в поле, а доступ в ЛК клиенту ещё не выдали.

### Шаг 6. Теги

Теги — плоский справочник меток экрана (**витрина**, **касса**, **фудкорт**). Создайте теги, затем привяжите их к экранам (Screen tags).

Зачем: клиент в разделе **«Группы экранов»** набирает флот из каталога и может отфильтровать экраны по тегам (экран должен иметь все выбранные теги).

На **«Мои экраны»** и **«Мои группы»** клиента теги не вешаются — это зона флота оператора.

### Шаг 7. Проверка, что клиенты могут войти

Выйдите, войдите как `manager@komandor.test`. В сайдбаре должны быть медиатека, ротации, группы экранов, локации (просмотр часов), медиапланы, экраны в эфире, мои экраны, мои группы.

## 4. Что ещё нужно оператору в повседневной работе

| Задача | Где |
|--------|-----|
| Добавить локацию / станцию / экран флота | Админка: Locations, Stations, Screens |
| Поправить часы работы | Админка локации. Клиент в ЛК «Локации» видит и может править часы **только** у локаций, где у него есть свои экраны; новые локации не создаёт |
| Теги и разметка экранов | Tags, Screen tags |
| Выдать доступ сотруднику клиента | Users: email, организация, роль, пароль |
| Снять или сдвинуть чужой медиаплан | Media plans: cancel / reschedule |
| Разобрать занятость сети | Media plans, Play logs |
| Служебный / нейтральный контент сети | Media assets в админке; видимость `network` — клиенты могут взять ролик в свою ротацию |

Режима «войти как клиент» нет. Оператор правит справочники и чужие планы в админке, не в ЛК клиента.

---

## 5. Чеклист пустой системы

1. Есть организация-оператор **Advertising company** и администратор.  
2. Созданы клиенты **Командор** и **Аллея**, у каждого — менеджер.  
3. Есть локации со часами работы и станции с токенами агента.  
4. Решено, какие экраны — флот без владельца, какие заведёт клиент.  
5. Заведены теги и проставлены на экраны флота, если клиенты будут собирать группы из каталога.  
6. Клиент может войти в ЛК и видит разделы контента.
