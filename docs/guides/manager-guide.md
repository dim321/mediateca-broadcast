# Гайд менеджера клиента: от ролика до эфира

Рабочая инструкция по размещению контента в системе трансляции. Описывает бизнес-процесс и правила, а не клики по каждому полю формы.

**Кому:** менеджер и администратор организации-клиента.  
**Оператор сети:** только там, где его участие нужно (флот экранов, аварийная отмена/перенос чужих планов).

---

## 1. Назначение и роли

В системе две оси: **тип организации** и **роль пользователя**.

### Организации

| Тип | Смысл |
|-----|--------|
| **Клиент** | Ваша компания: медиатека, ротации, группы точек, медиапланы |
| **Оператор** | Владелец рекламной сети: общий каталог экранов (флот), админка |

### Роли в организации-клиенте

| Роль | Что делает в личном кабинете |
|------|------------------------------|
| **Менеджер** | Ведёт весь контентный цикл: ролики → ротации → группы → медиапланы |
| **Администратор** | То же, что менеджер, плюс доступ к разделу финансов |
| **Бухгалтер** | Только финансы; контент и размещение недоступны |

**Оператор** — не отдельная роль пользователя в ЛК, а сотрудник организации-оператора. Работает в админке (`/admin`): ведёт локации, станции, экраны, теги и справочник сфер деятельности; оформляет **заказы на размещение** от имени клиентов; при необходимости отменяет или переносит медиапланы клиентов.

**Важно:** отдельного согласования «менеджер отправил → оператор одобрил» нет. Размещение медиаплана сразу занимает эфирный слот.

---

## 2. Общая схема процесса

```mermaid
flowchart LR
  A[Ролик] --> B[Ротация]
  B --> C[Группа точек]
  C --> D[Медиаплан]
  D --> E[Эфир на экранах]
```

| Этап | Кто ведёт | Результат |
|------|-----------|-----------|
| Загрузка ролика | Менеджер | Файл в статусе `ready` |
| Компоновка ротации | Менеджер | Упорядоченный набор готовых роликов |
| Группа точек | Менеджер (экраны — из каталога оператора) | Набор экранов для размещения |
| Медиаплан | Менеджер | Занятый слот: ротация + группа + окно времени |
| Контроль / изменения | Менеджер; при необходимости оператор | Смена ротации, перенос, отмена |

Параллельно оператор поддерживает **флот** (локации → станции → экраны и теги). Без актуального каталога экранов менеджер не соберёт группу точек.

---

## 3. Этап 1. Загрузка роликов

**Раздел:** медиатека (главная страница ЛК).

### Что делает менеджер

1. Загружает файл (видео, изображение и др. поддерживаемые форматы; лимит размера — до 1 ГБ).
2. Указывает **коммерческий тип** контента:
   - собственный (`own`);
   - коммерческий (`commercial`);
   - нейтральный (`neutral`);
   - служебный (`service`).
3. Указывает **видимость**:
   - только своя организация (`organization`);
   - доступен всем организациям сети (`network`) — чужие клиенты смогут взять ролик в свою ротацию.
4. Дожидается окончания обработки.

### Статусы обработки

```
pending → processing → ready
                    ↘ failed
```

| Статус | Смысл |
|--------|--------|
| `pending` / `processing` | Идёт разбор метаданных; для видео — ещё транскод в эфирный формат |
| `ready` | Ролик можно добавлять в ротацию |
| `failed` | Обработка не удалась; в ротацию не берётся — нужна повторная загрузка / разбор причины |

Для **видео** эфирная готовность строже: статус `ready` и подготовленный broadcast-файл. Пока идёт обработка, карточку в медиатеке система обновляет автоматически.

### Когда нужен оператор

Обычно не нужен. Вмешательство имеет смысл при системных сбоях обработки или вопросах по каталогу сети (через поддержку / админку оператора).

---

## 4. Этап 2. Компоновка ротации

**Раздел:** ротации.

Ротация — именованный **упорядоченный набор роликов**, который потом ставят в медиаплан. (В продукте это не «плейлист» как отдельная сущность — в системе используется термин **ротация**.)

### Что делает менеджер

1. Создаёт ротацию с уникальным в организации именем.
2. Добавляет ролики со статусом `ready` (свои или чужие с видимостью `network`).
3. Выстраивает порядок показа (в т.ч. перетаскиванием).
4. Проверяет, что все пункты готовы к эфиру — иначе медиаплан не создастся.

### Правила

- Один и тот же ролик в одной ротации — один раз.
- Неготовый ролик (`pending` / `processing` / `failed`) в ротацию добавить нельзя.
- Пустая ротация или ротация с неготовыми к эфиру роликами **не подойдёт** для размещения медиаплана.

### Когда нужен оператор

Не требуется для обычной компоновки. Оператор может просматривать/править контент в админке, но это не штатный шаг менеджера.

---

## 5. Этап 3. Группа точек трансляции

**Раздел:** группы точек трансляции.

Группа — **набор экранов**, на которых одновременно будет идти ваш медиаплан.

### Что делает менеджер

1. Создаёт именованную группу в своей организации.
2. Набирает экраны из **общего каталога** сети (фильтр по тегам, если они заданы оператором).
3. Убеждается, что в группе есть хотя бы один экран.

### Что делает оператор (предварительно / по запросу)

Оператор в админке ведёт флот:

- локации → станции → экраны;
- теги и привязку тегов к экранам (для фильтрации при наборе группы).

Менеджер **не создаёт и не редактирует** экраны — только выбирает их в группу. Каталог в ЛК — read-only; свой эфир на экране менеджер может посмотреть в разделе флота.

### Правила

- Группа без экранов → медиаплан создать нельзя.
- Экраны общие для сети: на одном экране в пересекающееся время может быть только одно подтверждённое занятие (см. этап 4).

---

## 6. Этап 4. Размещение медиаплана

**Раздел:** медиапланы.

Медиаплан — это и есть **занятие эфирного слота**: связка «ротация + группа точек + интервал времени». Отдельной «брони без контента» и квот секунд в продукте нет: создание активного медиаплана сразу занимает календарь.

### Что делает менеджер

1. Открывает создание медиаплана.
2. Выбирает группу точек и ротацию.
3. Задаёт окно показа (`starts_at` / `ends_at`) в часовом поясе организации.
4. Смотрит занятость экранов группы (занятые интервалы без указания чужой организации).
5. Сохраняет — при успехе план сразу **active**, слот занят.

### Правила конфликта (first-write-wins)

- На общих экранах пересечение с уже подтверждённым занятием **любой** организации запрещено.
- Кто первым успешно создал (или перенёс) план — тот удерживает слот; второй получает отказ, запись победителя не меняется.
- Внутри своей организации активные планы тоже не должны пересекаться на общих экранах.

### Предпосылки успешного размещения

| Проверка | Требование |
|----------|------------|
| Ротация | Все ролики broadcast-ready |
| Группа | Есть хотя бы один экран |
| Окно | Конец строго позже начала |
| Календарь | Нет пересечения с чужими/своими confirmed-занятиями на тех же экранах |

### Когда нужен оператор

На штатном размещении — нет. Оператор может помочь, если экраны некорректны в каталоге или нужно разобрать массовый конфликт занятости на сети.

## 6.1. Заказ на размещение

**Раздел:** заказы на размещение (ЛК) и `/admin` (оператор).

Заказ — коммерческий документ: контрагент, продукт, ролик, цены и дневная сетка выходов по группам экранов. При активации сетка разворачивается в обычные медиапланы (слоты эфира). Ручное создание слотов (этап 4) по-прежнему доступно.

### Что делает менеджер клиента

1. Создаёт черновик: шапка (ролик из медиатеки, продукт, коэффициент, скидка) и строки (группа экранов, цена за день, выходы по дням).
2. Число выходов в день должно делиться на часы работы группы; форма подскажет ближайшие допустимые значения.
3. Активирует заказ — система занимает окна эфира. Конфликтные дни остаются незанятыми, их можно занять повторно.
4. Печатает HTML-форму (приложение к договору). Замена ролика в активном заказе увеличивает версию документа и не пересоздаёт слоты.

### Что делает оператор

По просьбе клиента оформляет тот же заказ из `/admin`: выбирает организацию-контрагента, дальше форма та же. Заказ виден менеджерам клиента в ЛК; автором записи остаётся оператор. Отмена чужого заказа — тоже из админки.

---

## 7. Этап 5. Контроль и изменения

После размещения менеджер управляет планом в ЛК; оператор — в админке при необходимости.

### Действия менеджера

| Действие | Что меняется | Что нельзя |
|----------|--------------|------------|
| **Смена ротации** | Только ротация у активного плана | Окно и группу этим действием не меняют |
| **Перенос (reschedule)** | Окно и/или группа | Нужна повторная проверка занятости (как при создании) |
| **Отмена (cancel)** | План и внутренняя бронь → `cancelled` | Жёсткого удаления нет; слот освобождается |
| **Просмотр флота** | Свои активные планы на экране | Чужие организации на экране не показываются |

Статусы медиаплана для менеджера:

- `active` — в эфире / в календаре как занятие;
- `cancelled` — снято менеджером (или оператором), слот свободен;
- `invalidated` — системный/операторский съём с эфира (не основной путь клиента).

В список эфирных пакетов для станций попадают только **active**-планы с подтверждённой бронью в горизонте станции.

### Когда вмешивается оператор

| Ситуация | Действие оператора |
|----------|-------------------|
| Нужно снять чужой план с эфира | Cancel в админке |
| Нужно сдвинуть чужой план | Reschedule в админке |
| Проблема с экраном / тегом / станцией | Правка флота в админке |
| Выдача доступов сотрудникам клиента | Пользователи и роли в админке |

Режима «войти как клиент» (impersonation) в текущей версии нет: оператор правит через админку, а не через ЛК клиента.

## 8. Матрица действий

| Действие | Менеджер / админ клиента | Оператор сети | Бухгалтер |
|----------|--------------------------|---------------|-----------|
| Загрузка и правка своих роликов | да | да (админка) | нет |
| Сборка и правка ротаций | да | да (админка) | нет |
| Создание групп точек, набор экранов | да | да (админка) | нет |
| Ведение флота (локации, станции, экраны, теги) | нет (только просмотр каталога) | да | нет |
| Создание медиаплана (занятие слота) | да | через админку при необходимости | нет |
| Заказ на размещение (черновик → активация → печать) | да | да (от имени клиента в `/admin`) | только просмотр и печать |
| Смена ротации у плана | да | — | нет |
| Перенос / отмена своего плана | да | да (и чужих) | нет |
| Назначение ролей пользователям клиента | нет | да | нет |
| Финансы | администратор — да; менеджер — нет | да | да |

## 9. Ограничения и типовые ошибки

| Симптом / ограничение | Причина | Что делать |
|------------------------|---------|------------|
| Ролик не добавляется в ротацию | Ещё не `ready` или `failed` | Дождаться обработки или перезалить |
| Медиаплан не создаётся: ротация | Есть неготовые к эфиру ролики | Дождаться broadcast-ready / убрать проблемные |
| Медиаплан не создаётся: группа | Нет экранов в группе | Добавить экраны из каталога |
| Отказ при сохранении / переносе плана | Пересечение с занятым слотом (FWW) | Выбрать другое окно или другую группу |
| Нет нужных экранов в каталоге | Флот не заведён / не тегирован | Обратиться к оператору |
| Нет модерации перед эфиром | Так задумано: слот = медиаплан | Контролировать готовность контента до размещения |
| Нет отдельной «брони без роликов» | Продуктовая модель слота | Сначала ротация и группа, потом сразу план |
| Бухгалтер не видит медиатеку | Роль ограничена финансами | Работать под менеджером / администратором |

---

## Краткий чеклист менеджера

1. Загрузить ролик → дождаться `ready`.
2. Собрать ротацию и порядок показа.
3. Создать группу точек и набрать экраны.
4. Создать медиаплан (группа + ротация + окно) → слот занят.
   Либо оформить **заказ на размещение** (сетка дней → активация) — слоты создадутся из заказа.
5. При необходимости: сменить ротацию, перенести или отменить; по флоту — проверить свой эфир на экране.
6. Если экранов нет или слот «залип» у сети — подключить оператора. Оператор может оформить заказ за клиента из `/admin`.
