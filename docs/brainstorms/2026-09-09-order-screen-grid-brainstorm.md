# Сетка заказа по экранам, частота в час и общие окна эфира

Документ фиксирует продуктовую модель формы заказа на размещение: строка сетки = экран, частота и интервалы — на весь заказ, коммерческий эфир на экране общий. Проект ещё не в коммерческой эксплуатации: старые заказы с групповыми строками можно удалить, обратная совместимость сетки не нужна.

## What We're Building

Форма заказа (админка и кабинет) собирает один документ на набор отмеченных экранов.

На заказе: период «С / По», одно число «выходы в час», список суточных интервалов (09:00–12:00, 17:00–20:00, …). В сетке — строка на каждый отмеченный экран; ячейка дня показывает посчитанные выходы в день. Ячейку можно обнулить (этот экран в этот день не участвует). Цена, коэффициент и скидка на форме не запрашиваются.

При активации заказ не монополизирует окно. Несколько коммерческих заказов на один экран в одни часы делят эфир: ролики идут друг за другом по портрету экрана (приветствие, шапки блока, лимит подряд, нейтралка, промо владельца, мягкая квота).

## Why This Approach

- **Строка = экран, не группа.** Произвольный набор из таблицы (флот и чужие организации) не совпадает с именованной `BroadcastPointGroup`. Часы работы и нули в ячейках — per screen. Скрытая группа «экраны этого заказа» ломает обнуление одного экрана и засоряет флот. Только UI поверх групповых строк не покрывает каталог и разные часы.
- **Частота и интервалы на заказ.** Один документ — одна частота и один набор окон; дневные выходы различаются, потому что у экранов разные рабочие часы и разное пересечение с окнами.
- **Эфир общий, не FWW на окно заказа.** Эксклюзивный occupy «полночь–полночь» на группу противоречит портрету: коммерция — доля часа, не бронь интервала. `ScreenOverlapGuard` для пересечения коммерческих планов заказов на одном экране не действует как отказ; плейлист берёт все такие планы часа, не один.

## Key Decisions

### Форма (админка и кабинет)

- Шапка: продукт, ролик, тип размещения. Без цены, коэффициента, скидки.
- Период и частота на весь заказ: даты «С / По»; `shows_per_hour`; список интервалов «с / по» (добавить / удалить).
- Выбор экранов: полный каталог (`Screen.operator_catalog` — флот и все организации). Фильтры по колонкам только сужают таблицу. В заказ попадают отмеченные чекбоксами экраны.
- Сетка: одна строка на отмеченный экран (имя, локация, станция). Нет селекта группы, нет «добавить строку». Снятие галочки убирает строку.
- Ячейка дня: выходы в день = `shows_per_hour ×` часы пересечения интервалов заказа с эффективными рабочими часами **этого** экрана в эту дату (календарь заказа — TZ организации-клиента; часы экрана — TZ локации). Нет пересечения → 0. Редактирование ячейки — только в 0 (не размещаем). Обнулённую ячейку при пересчёте частоты/интервалов не затираем.
- Суббота и воскресенье в TZ организации заказа подсвечиваются. Подсветка не обнуляет ячейку сама.

### Данные

- `advertising_orders.shows_per_hour` — integer, частота на весь заказ.
- `advertising_order_windows` — часы «с» и «по» без даты; несколько окон на заказ.
- `advertising_order_lines` привязаны к `screen_id`, unique `(advertising_order_id, screen_id)`. `broadcast_point_group_id` у строк убираем. Цену в строке на форме не используем (колонку можно оставить с default 0).
- `advertising_order_line_days`: запись с `shows > 0` — участвуем; нет записи — день пропущен (обнулили). В `shows` пишем уже посчитанное дневное число (сумма по всем окнам дня).
- Старые заказы с групповыми строками удаляем. Миграция схемы ломающая, без разворота групп в экраны при открытии формы.

### Активация и эфир

- Для каждой строки-экрана и каждого дня с `shows > 0`: пересечь окна заказа с рабочими часами экрана; каждый получившийся отрезок — заявка плана на этот экран с `shows_per_hour` заказа.
- Медиаплан заказа — заявка «участвовать в эфире», не эксклюзивная бронь окна. Два коммерческих заказа на один экран и 09:00–12:00 оба допустимы.
- Плейлист часа собирает **все** такие планы экрана и раскладывает по портрету: welcome/close по часам работы; шапки начала/конца рекламного блока; ролики клиентов друг за другом, не больше `max_commercial_in_row`; у каждого заказа — свои `shows_per_hour`; остаток — нейтральный филлер и собственное промо владельца; коммерческая квота — soft, flash, без отката occupy.
- Нулевая ячейка: этот заказ в этот день не входит в эфир; другие заказы на том же экране продолжают играть.
- Текущий генератор берёт один occupying-план на слот (`occupying_plan_for`) — его нужно сменить на все коммерческие планы экрана в этом часе. Guard не должен отвергать пересечение коммерческих заявок заказов на одном экране.

### Вне скоупа этого шага

- Цена, коэффициент, скидка на форме (поля шапки/строки в БД можно не удалять).
- Переактивация и переписывание уже существующих групповых слотов: заказы удаляем.
- Кабинетный каталог уже не режется группами организации — полный флот, как в админке.

## Open Questions

- Техническая форма «заявки» на экране: расширить `MediaPlan` экраном/`screen_ids` vs ослабить Guard только для `advertising_order_line_id`. Решение — на этапе плана; продукт: план занимает перечисленные экраны, не именованную группу заказа.
- Нужны ли интервалы через полночь (22:00–02:00). В форме не закладываем, пока не попросили.
