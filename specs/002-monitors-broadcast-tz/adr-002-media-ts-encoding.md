# ADR-002: подготовка эфирного MPEG-TS

## Контекст

Hub получает разные допустимые типы медиа, но для эфира видеоролик должен иметь единый
артефакт, пригодный для выдачи Агенту. Медиа-план и Package API находятся вне этого этапа.

## Решение

После успешного извлечения метаданных видео передаётся в `MediaTranscodeJob`. Он создаёт
`broadcast_file` в Active Storage с MIME-типом `video/mp2t` и профилем:

- контейнер MPEG-TS;
- H.264 High@4.1, до 1080p, 25 fps, `gop=25`;
- AAC, 48 kHz, 128 kbps;
- video/audio PTS начинаются с нуля.

Используется единственный существующий enum `MediaAsset#processing_status`:
`pending → processing → ready|failed`. `ready` для видео означает, что `broadcast_file`
успешно прикреплён. Ошибка ffmpeg переводит файл в `failed` и сохраняет её класс и текст в
`metadata`.

Изображения, аудио, документы и презентации не транскодируются. После метаданных они сразу
становятся `ready`; для них `broadcast_file` не создаётся.

Размер исходного файла ограничен 1 GiB при создании `MediaAsset`.

## Последствия

Потребители будущих MediaPlan и Package API могут выбирать видео только при `ready` и
наличии `broadcast_file`. Повторная обработка готового видео не перезаписывает существующий
эфирный файл.
