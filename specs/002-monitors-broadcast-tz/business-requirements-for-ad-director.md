## Как читать этот документ

Оценивайте:

1. Решает ли система ваши коммерческие задачи?
2. Удобны ли роли, бронирование и отчёты для работы с клиентами сети?

Технические детали (железо, протоколы, серверы, кодирование) сюда **не включены** — они не влияют на оценку бизнес-функционала.

## 1. Суть продукта (одной страницей)

| Поле | Значение |
| ---- | -------- |
| **Цель** | Управлять сетью экранов в торговых/сервисных точках и показывать рекламные и сервисные материалы по расписанию |
| **Где** | Магазины, аптеки, кафе, МОП (лифт, холл, зона ожидания и т.п.) |
| **Заказчик системы** | Оператор рекламной сети (владелец всех точек) |
| **Клиент сети** | Отдельная организация со своим личным кабинетом; сама бронирует свободное эфирное время |
| **Что в эфире** | Видео, статичные макеты, сервисные материалы, нейтральный «заполнитель» пустот |
| **Ключевой цикл в ЛК** | Ролики → **ротация** → **группа точек** → бронь квоты → **медиаплан** |

---

## 2. Бизнес-цели

1. Централизованно управлять парком экранов в партнёрских сетях.
2. Размещать коммерческий, собственный и нейтральный контент с учётом квот эфирного времени.
3. Давать организациям изолированный личный кабинет с ролями, фильтрами и отчётностью.
4. Обеспечивать непрерывную работу экранов (включение/мониторинг — как бизнес-ожидание «эфир не должен молчать»).
5. Гибко размечать точки признаками (тегами) для поиска и таргетинга без жёсткой иерархии фильтров.
6. *(Перспектива)* Подключить ИИ для классификации контента (сфера деятельности и др.).

---

## 3. Кто чем владеет и кто что видит

### 3.1. Модель владения

- Все точки принадлежат **только оператору** рекламной сети.
- Клиент сети — отдельная организация со своим ЛК; точка клиенту **не принадлежит**.
- На одной точке могут быть эфирные блоки **нескольких клиентов**.
- Клиент видит **весь парк точек** оператора (каталог для выбора).
- Клиент **сам выбирает и бронирует** свободные квоты / эфирные блоки.
- В содержимом эфира клиент видит **только свой** забронированный блок (чужой эфир скрыт).
- Оплата **сразу после бронирования не требуется** (бронь ≠ платёж).

### 3.2. Роли в личном кабинете клиента

| Роль | Что может |
| ---- | --------- |
| **Менеджер** | Загрузка медиа; ротации; именованные группы точек; бронирование, отмена и перенос квот; медиапланы |
| **Бухгалтер** | Финансовые отчёты |
| **Администратор** | Весь функционал ЛК клиента |

Можно добавлять новые роли и настраивать права без перестройки системы.

### 3.3. Оператор сети

- Сотрудники оператора работают в **админ-панели оператора** (не в отдельном «ЛК оператора»).
- Оператор видит **все устройства**, **всех клиентов**, **все квоты** и может отменять/переносить брони клиентов.
- **«Режим клиента»**: одним кликом войти в ЛК клиента с правами администратора этого клиента; в истории действий видно «сделано оператором X» (не маскируется под пользователя клиента).

## 4. Жизненный цикл коммерческого размещения (зафиксировано)

Рабочий процесс менеджера клиента в ЛК:

```text
1. Загрузка рекламных роликов в медиатеку
        ↓
2. Компоновка роликов в именованный набор — «ротация»
   (в исходном ТЗ это называлось «плейлист»)
        ↓
3. Создание именованной группы точек трансляции
        ↓
4. Бронирование квоты на этой группе точек
   в определённое время под проигрывание ротации
        ↓
5. Привязка ротации к группе точек по расписанию — «медиаплан»
```

| Сущность | Что это |
| -------- | ------- |
| **Ролик** | Загруженный рекламный (или иной) материал в медиатеке |
| **Ротация** | Именованный набор роликов, составленный менеджером (вместо термина «плейлист») |
| **Группа точек трансляции** | Именованный набор точек (экранов Android TV), на которых планируется показ |
| **Квота / бронь** | Закреплённое эфирное время на группе точек под трансляцию |
| **Медиаплан** | Привязка **ротации** к **группе точек** по **определённому расписанию** (когда и где крутится ротация) |

Отдельные сущности «заказ» и «размещение» в этой модели **не выделяются**: коммерческая единица постановки в эфир — **медиаплан**.

## 5. Бронирование эфирного времени (ядро коммерции)

| Правило | Описание |
| ------- | -------- |
| Объект брони | Квота на **группе точек трансляции** (не обязательно по одной точке) |
| Фиксация | Бронь слота — **сразу** (без ожидания модерации и без «hold» с таймером) |
| Конфликт | Кто первый успел — тот занял слот; второй получает отказ |
| Переполнение квоты | Превышение — отклоняется |
| Отмена / перенос | Может менеджер клиента и оператор |
| Куда переносить | На **любую точку / группу** парка, но только на **свободный** целевой слот |
| Если цель занята | Перенос отклоняется, **исходная бронь сохраняется** |
| Приоритет при переносе | «Я уже держал старый слот» **не даёт** преимущества на новый |

Единица квоты — **секунда**. Клиент видит остаток свободного времени и свободные слоты для бронирования.

## 6. Что система должна уметь (по блокам)

Шкала приоритета:

| Приоритет | Смысл |
| --------- | ----- |
| **Обязательно** | Без этого система не решает заявленную задачу |
| **Желательно** | Важно для удобства/коммерции, можно во 2–3 итерации |
| **Опционально** | «На вырост», не блокирует запуск |

### 6.1. Точки и экраны

| ID | Требование | Приоритет |
| -- | ---------- | --------- |
| FR-01.1 | Сеть мониторов; в локации ≥1 монитор; зоны внутри локации | Обязательно |
| FR-01.2 | Ориентация экрана: горизонтальная / вертикальная | Обязательно |
| FR-01.3 | Экран со своим расписанием **или** группа экранов, идущих почти синхронно (расхождение до ~2 с — допустимо) | Обязательно |
| FR-01.4 | Экраны разного назначения (аптека / меню / зал) | Желательно |
| FR-01.5 | У экрана — неограниченный набор признаков (тегов) | Обязательно |
| FR-01.6 | Фильтры по признакам работают параллельно (можно комбинировать, без «древовидного» сужения как в интернет-магазине) | Обязательно |
| FR-01.7 | Права на экран через признаки (статистика, постановка в эфир) | Желательно |
| FR-01.8 | Группы баз вещания организации (в т.ч. вложенные) | Желательно |

**Примеры признаков:** только видео / только аудио / аудио-видео · меню / сервис / рекламный · регион · город · сеть · зона (Вход, Касса, Хлеб…).

| ID | Требование | Приоритет |
| -- | ---------- | --------- |
| FR-03.1 | Статичные макеты и видео (до Full HD / 4K); макс. размер файла **1 ГБ** | Обязательно |
| FR-03.2 | Шаблоны статичных изображений с зонами: фото/текст (название, цена, граммовки…) | Желательно |
| FR-03.3 | Типы контента: собственный / коммерческий / нейтральный (справочник расширяемый) | Обязательно |
| FR-03.4 | Сервисные материалы: показ **1 раз в день** в **фиксированное время** | Желательно |
| FR-03.5 | Общие базы нейтрального контента для заполнения пустот (в т.ч. между организациями) | Обязательно для сети с несколькими клиентами |

**Форматы (как ожидание бизнеса):** видео, изображения, аудио, презентации, PDF.

**Вне этого продукта:** отдельная CMS для «живых» динамических меню кафе — отдельный проект.

| ID | Требование | Приоритет |

| ID | Требование | Приоритет |

| FR-06.7 | Вставки поверх / внутрь эфира | Желательно |
| FR-06.8 | Ограничители выхода: дата **и** время (не только дата) | Обязательно |
| FR-06.9 | Автозаполнение свободного времени из спец. базы | Желательно |

частота 20′ → 4 коммерческих подблока по 2′ → после каждого нейтральная заставка 3′ → нейтральные по возможности не повторяются день за днём (при малом пуле — повтор допустим).

## 7. Что внутри продукта, а что снаружи

**Внутри (нужно для запуска коммерции):**

- Регистрация точек/экранов, ориентация, признаки
- Загрузка макетов и видео; шаблоны со зонами (поэтапно)
- Ротации: цикл / точное время / заполнение пустот
- Группы точек, бронь квот, медиапланы
- Разделение эфирного времени между организациями и типами контента
- ЛК клиента с ролями
- Отчёты: выходы, загруженность, фин. калькуляторы; экспорт XLS/PDF (без ЭП и печати)
- Непрерывная работа экранов (вкл./мониторинг как бизнес-ожидание)

**Снаружи / отдельно:**

- CMS для динамических меню вне шаблонов
- Отдельное native-приложение для телефона
- Онлайн-оплата сразу после брони
- Печать / электронная подпись финансовых документов
- Юридические и лицензионные аспекты контента

## 8. Сквозные сценарии (для проверки «понятно ли бизнесу»)

### A. Запуск точки

Оператор регистрирует локацию → экраны → ориентацию → признаки → делит эфирное время между организациями → назначает нейтральный пул.

### B. Коммерческое размещение (основной путь)

Менеджер клиента в ЛК:

1. загружает ролики;
2. собирает **ротацию**;
3. создаёт именованную **группу точек** трансляции;
4. бронирует квоту на группе в нужное время;
5. получает **медиаплан** (ротация ↔ группа точек ↔ расписание).

Оператор при необходимости заходит в ЛК клиента («режим клиента»).

### C. Циклический день

На точке собирается блок ~20′: коммерция + нейтральные прослойки (повтор при малом пуле допустим) → цикл крутится; в заданные HH:MM вставляются точные ролики (они важнее цикла).

### D. Меню в кафе

Оператор выбирает шаблон → правит зоны (блюдо, цена, фото) → публикует на экраны с признаком «меню».

### E. Отчётность

Менеджер выгружает справку выходов / упрощённую справку / фин. разбивку / загруженность (XLS/PDF, без подписи и печати).

## 10. Ожидания по масштабу, доступности и хранению

| Тема | Значение |
| ---- | -------- |
| Пилот | ~**200** точек / ~**100** организаций |
| Через год | ~**10 000** точек / ~**5 000** организаций |
| ЛК | Доступность **14 часов × 7 дней** |
| Экраны | Эфир **24/7** |
| При пропаже связи на точке | Показ из заранее загруженного запаса контента (окно по умолчанию **сутки**, настраивается оператором) |
| Логи / история показов | Хранение **2 месяца** |
| Фин. документы | Экспорт XLS/PDF; **печать и ЭП не нужны** |

## 11. Глоссарий для бизнеса

| Термин | Простыми словами |
| ------ | ---------------- |
| **Оператор** | Владелец сети экранов и заказчик системы |
| **Клиент сети** | Рекламодатель / организация со своим ЛК; бронирует эфир |
| **Локация** | Магазин, кафе, зона; у одного названия могут быть разные юрлица |
| **Экран / монитор / точка трансляции** | Устройство показа в точке (Android TV) |
| **База вещания** | Группа точек организации (например, только видео или только аудио) |
| **Группа точек трансляции** | Именованный набор точек, создаваемый менеджером для брони и медиаплана |
| **Квота / эфирный блок** | Выделенное время на группе точек для клиента |
| **Бронирование** | Мгновенное закрепление свободного слота за клиентом |
| **Ролик / контент** | Файл или шаблон к размещению |
| **Ротация** | Именованный набор роликов (в исходном ТЗ — «плейлист») |
| **Медиаплан** | Привязка ротации к группе точек по определённому расписанию |
| **Эфирная сетка** | План эфира точки/группы на период с квотами и блоками |
| **Циклическая ротация** | Набор, который крутится снова и снова |
| **Ротация по таймингу** | Жёсткие выходы в заданное время |
| **Нейтральный контент** | Заполнители / атмосфера, когда нет коммерции; при малом пуле повтор допустим |
| **Признак (тег)** | Произвольная метка для фильтрации и таргетинга |

## 13. Чек-лист для оценки директором по рекламе

Отметьте «да / нет / уточнить» по каждому пункту:

- [ ] Понятна модель: оператор владеет точками, клиент бронирует эфир сам
- [ ] Понятен цикл: ролики → ротация → группа точек → бронь → медиаплан
- [ ] Роли менеджер / бухгалтер / администратор покрывают работу команды клиента
- [ ] Правила брони (мгновенно, кто первый — тот занял, перенос только на свободный слот) приемлемы коммерчески
- [ ] Достаточно сценариев эфира: цикл + точные выходы + нейтральное заполнение
- [ ] Отчёты по выходам и (позже) фин. долям закрывают продажи и закрытие месяца
- [ ] XLS/PDF без печати и ЭП — достаточно
- [ ] Хранение логов 2 месяца — достаточно
- [ ] Шаблоны меню/ценников можно отложить, если на старте хватает готовых макетов
- [ ] Оплата после брони не нужна на первом этапе — согласовано
- [ ] Масштаб пилота 200 точек / 100 орг. — реалистичен
